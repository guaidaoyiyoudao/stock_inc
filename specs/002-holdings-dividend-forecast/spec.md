# Feature Specification: Holdings Dividend Forecast

**Feature Branch**: `002-holdings-dividend-forecast`
**Created**: 2026-04-12
**Status**: Draft
**Input**: User description: "用户新增股票的时候，支持填写持有的股票数，并根据可选择的平均股息率，计算接下来的股息收入"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Record Stock Holdings (Priority: P1)

用户在添加股票时，可以填写自己持有的股票数量。添加完成后，股票卡片和详情页展示用户的持仓数量以及根据历史股息数据计算出的每股派息金额。用户也可以在添加后随时修改持仓数量。

**Why this priority**: 持仓数量是所有收入计算的基础，没有持仓数据就无法进行任何股息收入预测。这是本功能的 MVP。

**Independent Test**: 可以通过添加一只股票并输入持仓数量，验证卡片上是否正确显示持仓数量来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在添加股票页面选择了某只股票, **When** 用户在"持有股数"输入框中输入数量（如1000）并确认, **Then** 该股票被添加到列表中，股票卡片显示持有1000股
2. **Given** 用户已添加一只股票（持有1000股）, **When** 用户在股票详情页点击"编辑持仓"并修改数量为2000, **Then** 卡片和详情页实时更新为持有2000股
3. **Given** 用户在添加股票页面, **When** 用户不填写持有股数直接确认, **Then** 系统默认持仓为0股，卡片上不显示持仓相关收入信息

---

### User Story 2 - Forecast Dividend Income by Average Yield (Priority: P2)

用户想要预估自己未来的股息收入。系统根据用户选择的历史平均股息率（1年、3年、5年），乘以用户持仓数量，计算出该股票的预期年度股息收入。主页汇总展示所有股票的预期股息收入总和。

**Why this priority**: 股息收入预测是本功能的核心价值，在持仓数据基础上提供前瞻性分析，帮助用户规划投资收益。

**Independent Test**: 可以通过添加一只股票、输入持仓数量、选择某个平均股息率，验证预测收入是否正确计算来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户持有平安银行1000股且该股票有历史股息数据, **When** 用户选择"3年平均股息率", **Then** 系统展示该股票的预期年度股息收入 = 1000 × 3年平均每股派息金额
2. **Given** 用户持有多只股票, **When** 用户打开主页, **Then** 主页顶部展示所有股票的预期股息收入总和
3. **Given** 用户查看某只股票详情页, **When** 用户切换不同的平均股息率选项（1年/3年/5年）, **Then** 预测收入数据实时更新
4. **Given** 某只股票历史股息数据不足所选年限（如只有2年数据但选了5年平均）, **Then** 系统基于现有年份数据计算平均值，并在界面上标注实际使用了几年数据

---

### User Story 3 - Compare Yield Scenarios (Priority: P3)

用户想要对比不同股息率情景下的收入差异。在股票详情页，系统同时展示基于1年、3年、5年平均股息率的预测收入，让用户一眼看出不同假设下的收入预期。

**Why this priority**: 多情景对比是高级分析功能，增强用户决策能力，但不影响基本的收入预测功能。

**Independent Test**: 可以通过查看股票详情页，验证是否同时展示了多种股息率情景的预测收入来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户查看某只股票的详情页, **When** 页面加载完成, **Then** 同时展示1年、3年、5年平均股息率下的预测收入
2. **Given** 用户查看汇总页, **When** 各股票使用了不同的默认平均股息率, **Then** 汇总收入基于每只股票各自选择的股息率计算

---

### Edge Cases

- **EC-001**: 用户输入的持有股数为0或负数时，系统 MUST 将其视为0，不展示该股票的收入预测
- **EC-002**: 股票没有历史股息数据时，系统 MUST 在预测区域显示"暂无历史数据，无法预测"提示
- **EC-003**: 用户修改持仓数量后，所有依赖持仓计算的收入数据 MUST 立即更新
- **EC-004**: 用户删除某只股票后，汇总预测收入 MUST 自动扣除该股票的贡献

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户在添加股票时填写持有的股票数量
- **FR-002**: 系统 MUST 允许用户在股票详情页通过"编辑持仓"入口跳转至独立的编辑页面修改持有数量（独立页面设计，便于后续扩展更多可编辑字段）
- **FR-003**: 系统 MUST 在股票卡片上展示用户的持仓数量和预测股息收入
- **FR-004**: 系统 MUST 根据历史股息数据计算1年、3年、5年平均每股派息金额
- **FR-005**: 系统 MUST 允许用户在股票详情页选择使用哪个平均股息率进行收入预测（1年/3年/5年），默认为3年，且用户的选择 MUST 被持久化保存
- **FR-006**: 系统 MUST 根据用户持仓数量和所选平均股息率计算预期年度股息收入
- **FR-007**: 系统 MUST 在主页展示所有股票的预期股息收入总和，每只股票默认使用3年平均股息率，用户在详情页切换的档位会影响汇总计算
- **FR-008**: 系统 MUST 在股票详情页同时展示多种平均股息率下的预测收入对比
- **FR-009**: 系统 MUST 在历史数据不足所选年限时，基于可用年份数据计算平均值并标注实际年限
- **FR-010**: 系统 MUST 将持仓数量和每只股票的股息率档位选择持久化存储在本地
- **FR-011**: 系统 MUST 在持仓数据变更后立即更新所有相关的收入计算

### Key Entities

- **持仓(Holding)**: 用户对某只股票的持有数量，与股票一一关联
- **平均股息率(Average Dividend Rate)**: 基于历史股息记录计算的平均每股派息金额，按不同时间窗口（1年/3年/5年）分组
- **股息收入预测(Dividend Forecast)**: 根据持仓数量 × 平均每股派息金额计算的预期年度股息收入

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在5秒内完成持仓数量的输入或修改
- **SC-002**: 预测收入计算在用户切换股息率选项后1秒内完成更新
- **SC-003**: 90%的用户能直观理解预测收入是基于历史平均值的估算
- **SC-004**: 汇总预测收入与各股票预测收入之和完全一致

## Assumptions

- 持仓数量为整数，单位为"股"
- 平均股息率基于已有的历史股息记录计算，不引入外部数据源
- 主页汇总默认使用3年平均股息率，用户可在详情页切换后影响汇总
- 预测收入仅为估算值，不构成投资建议，界面上须注明"仅供参考"
- 股息收入预测基于每股派息金额（税前），不涉及税后计算
- 用户可在添加股票时跳过填写持仓数量（默认为0），之后随时补充
- 预测计算使用算术平均值，不使用加权平均或其他统计方法
- 依赖 001-stock-dividend-tracker 功能提供的股票和股息数据
- 本次不包含自定义输入股息率功能，仅提供1年/3年/5年三档历史平均值选项

## Clarifications

### Session 2026-04-12

- Q: US2 描述中提到"1年、3年、5年或自定义"平均股息率，自定义输入是否纳入本次功能范围？ → A: 不纳入：仅提供1年/3年/5年三档历史平均值选项
- Q: 用户修改持仓数量的交互方式是什么？ → A: 在股票详情页提供"编辑持仓"入口，进入编辑模式修改
- Q: 主页汇总预测收入时，每只股票使用哪个平均股息率来计算？ → A: 每只股票默认使用3年平均股息率计算汇总，用户可在详情页切换后影响汇总
- Q: 用户在详情页切换股息率档位后，该选择是否需要持久化？ → A: 持久化：用户切换的档位被保存，下次打开详情页时仍为上次选择的档位
- Q: 股票卡片上除了展示持仓数量外，是否也展示该股票的预测股息收入？ → A: 卡片同时展示持仓数量和预测股息收入

### Session 2026-04-12 (Clarify Round 2)

- Q: 用户在股票详情页编辑持仓数量时，使用哪种 UI 交互模式？ → A: 独立的编辑页面（而非内联对话框），便于后续扩展更多可编辑字段
