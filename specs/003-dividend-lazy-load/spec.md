# Feature Specification: Dividend Lazy Loading

**Feature Branch**: `003-dividend-lazy-load`
**Created**: 2026-04-15
**Status**: Draft
**Input**: User description: "股票详情页中，分红数据不要显示，而是向下滑动时，动态加载显示，默认先显示5年的数据"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Default 5-Year Dividend Display (Priority: P1)

用户打开股票详情页时，分红记录区域默认只显示最近5年的分红数据，页面加载快速且流畅。用户可以看到"分红记录"标题旁边显示已加载数据的总条数。

**Why this priority**: 这是核心体验变更——将一次性加载全部数据改为按需加载，5年默认展示是最基础的交互需求。

**Independent Test**: 可以通过打开一个有超过5年分红记录的股票详情页，验证初始只显示5年数据来独立测试。

**Acceptance Scenarios**:

1. **Given** 一只股票有10年的分红记录, **When** 用户进入该股票的详情页, **Then** 分红记录区域只显示最近5年的数据，页面加载无明显延迟
2. **Given** 一只股票只有3年的分红记录, **When** 用户进入该股票的详情页, **Then** 分红记录区域显示全部3年数据
3. **Given** 一只股票刚好有5年分红记录, **When** 用户进入该股票的详情页, **Then** 显示全部5年数据，无"加载更多"提示

---

### User Story 2 - Scroll-to-Load-More (Priority: P2)

用户在分红记录区域向下滑动，当滑动到已显示数据的底部附近时，系统自动加载更早年份的分红数据并追加到列表中。加载过程中显示加载指示器。

**Why this priority**: 动态按需加载是本功能的关键交互，确保用户可以浏览全部历史数据。

**Independent Test**: 可以通过打开有多于5年分红记录的股票，滚动到底部触发加载来独立测试。

**Acceptance Scenarios**:

1. **Given** 已显示5年分红数据且还有更早年份未加载, **When** 用户滑动到列表底部附近, **Then** 系统自动加载并追加更早年份的分红记录
2. **Given** 正在加载更多数据, **When** 加载进行中, **Then** 列表底部显示加载指示器（如旋转图标）
3. **Given** 已加载全部历史分红数据, **When** 用户滚动到列表底部, **Then** 不再触发加载，不显示加载指示器

---

### User Story 3 - 分红记录计数准确显示 (Priority: P3)

"分红记录"标题旁的计数徽章应反映当前已加载的记录数量，而非总记录数量。随着用户滚动加载更多数据，计数应动态更新。

**Why this priority**: 这是次要但重要的信息准确性需求，帮助用户了解当前浏览进度。

**Independent Test**: 可以通过观察加载前后的计数变化来独立测试。

**Acceptance Scenarios**:

1. **Given** 初始加载了5年数据共5条记录, **When** 用户查看分红记录标题, **Then** 计数徽章显示"5"
2. **Given** 用户滚动加载了更多数据，共加载了10条记录, **When** 用户查看分红记录标题, **Then** 计数徽章更新为"10"

---

### Edge Cases

- 股票完全没有分红记录时，保持现有的空状态展示（"暂无股息数据"），不显示"加载更多"
- 分红数据按年份分组时，同一年份有多条记录（如中期分红、年末分红），5年计数按记录条数计算而非按年计算
- 数据源返回异常或为空时，已加载的数据不受影响，加载指示器消失
- 用户快速反复滚动时，不应触发重复加载请求

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统在进入股票详情页时，分红记录区域默认只加载并显示最近5年的分红数据
- **FR-002**: 当用户向下滑动分红记录列表接近底部时，系统自动触发加载更早年份的分红数据
- **FR-003**: 加载更多数据时，列表底部必须显示加载状态指示器
- **FR-004**: 新加载的数据必须平滑追加到现有列表末尾，不替换已显示的数据
- **FR-005**: 当全部历史分红数据已加载完毕时，不再触发加载请求
- **FR-006**: "分红记录"标题旁的计数徽章必须显示当前已加载的记录条数，并随加载动态更新
- **FR-007**: 分红数据按时间倒序排列（最新年份在前），每次加载追加的是更早年份的数据
- **FR-008**: 防止并发加载——在一次加载完成之前，不应触发新的加载请求

### Key Entities

- **DividendRecord**: 分红记录实体，包含报告日期、每股现金、除息日、计划状态、股息率等属性。已有实体，无需修改。
- **PaginatedDividendList**: 分页加载的分红列表视图状态，追踪已加载的记录集合、是否还有更多数据可加载、当前是否正在加载。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 股票详情页初始加载时，分红记录区域在1秒内呈现最近5年的数据
- **SC-002**: 滚动到底部触发加载时，新数据在2秒内追加显示到列表中
- **SC-003**: 用户可以通过持续滚动浏览任意长度的历史分红数据，无需手动翻页操作
- **SC-004**: 快速滑动过程中无重复加载、无闪烁、无已加载数据丢失

## Assumptions

- 所有分红数据已存储在本地数据库中，无需网络请求即可加载
- "5年"指当前年份往前推5个自然年的分红记录数据量，按实际记录条数加载
- 分红记录的排序方式保持不变（按报告日期倒序）
- 股票详情页的其他区域（持仓信息、预测卡片等）不受此变更影响
- 数据库中已有的分红数据结构和字段保持不变
