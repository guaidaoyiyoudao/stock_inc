### H1. FundDataRepository 三处合并方向写反——缓存覆盖远端，修正永不自愈
`app/src/main/java/com/stock/dividend/data/repository/FundDataRepository.kt` | 80-82, 152-153, 196-197 | bug
getHoldings / getNav / reportDates 的 merge lambda 写成 `fresh.associateBy{...} + cached.associateBy{...}`——Kotlin Map `+` **右侧覆盖左侧**，实际效果是缓存覆盖远端同期数据，与类文档、FuyaoCacheStore 语义①「远端覆盖同期、缓存独有旧期永续保留」正相反（同文件 getHoldersDetail / getIndustryAllocation 的正确写法反衬为笔误）。后果：①扶摇侧修正历史报告期数据（持仓比例、净值精度）永远停在首次缓存值，且 merge 结果每次回写持久化，无自愈路径；②`endDateMs`/`navDateMs` 可空，多条 null-key 条目 associateBy 塌缩丢行。
**修复**：交换为 `cached.associateBy{...} + fresh.associateBy{...}`；补「同报告期冲突远端胜出」单测（现测试只测了不同期并集，恰是盲区）。

### H2. fetchIndexDailyBars 同型合并方向反——指数日K收盘价被锁死在盘中缓存值
`app/src/main/java/com/stock/dividend/data/repository/MarketDataRepository.kt` | 678-720 | bug
`(fresh.associateBy { it.date } + c.associateBy { it.date })` 同 H1 方向反。指数日K是「历史不可变」数据，但当日 bar 在盘中首次缓存后，次日增量拉到真实收盘价会被缓存旧值覆盖并回写——污染不可自愈。
**修复**：交换操作数；补 merge 方向单测。

### H6. PlaneInFlight 共享 Deferred 挂在首个调用者作用域——取消级联 + 假失败负缓存
`app/src/main/java/com/stock/dividend/data/plane/PlaneInFlight.kt` | 22-37 | bug

**修复**：让 block 运行在独立作用域（SupervisorJob + CompletableDeferred 广播，或 owner 以 NonCancellable 收尾），并补取消传播测试。关联：同文件 25 行 `takeIf { it.isActive }` 对 LAZY 未 start 的 Deferred（New 态）返回 false，锁内注册/锁外 start 的窗口内并发调用者会新建重复请求——改 `!it.isCompleted` 或锁内完成 start。
